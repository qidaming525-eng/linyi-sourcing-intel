# directing-playbook.md — 短视频编导方法库 / Living Directing Playbook

> 目的：把外部优秀方法、Damon 的现场经验、以及账号发布后的真实数据，持续沉淀成一个**可更新、可测试、可淘汰**的编导方法库。
>
> 本文件不是“永远正确的圣经”。方法可以新增、测试、升级、合并或退休。
> GitHub `main` 仍是唯一知识主库；任何方法只有经过 Damon + ChatGPT 决策后，才能从候选升级为项目默认规则。

---

## 1. 状态 / Status

每条编导原则必须使用以下状态之一：

- `candidate` — 外部研究 / 新想法，尚未用于 Damon 内容
- `testing` — 正在 1–3 条真实视频里试用，等待数据与现场反馈
- `adopted` — Damon + ChatGPT 已确认，作为当前默认方法
- `retired` — 已不再适合当前账号，保留历史但不再默认使用

**WorkBuddy 可以新增 `candidate`，但不得自行升级为 `testing` / `adopted`，不得直接修改 approved 脚本。**

---

## 2. 方法条目格式 / Principle Card

每条方法尽量用以下最小字段，不做过度文档化：

```text
ID: DIR-xxx
Name / 名称:
Status:
Added:
Source / 来源:
What it means / 核心意思:
Why it may work / 为什么可能有效:
Best use / 适用场景:
Risk / 风险或不适用场景:
How Damon can test it / Damon 怎么测试:
Evidence from our account / 我们账号的验证结果:
Last reviewed:
```

外部方法不得只写结论；至少保留**来源 URL + 发布日期（能确认时）+ 来源类型**。

## 3. 我们重点积累的编导能力 / Directing Dimensions

后续研究优先沉淀到以下维度：

1. `topic` — 选题：为什么这个问题值得拍
2. `hook` — 前 1–5 秒：冲突 / 结果 / 数字 / 问题 / 视觉钩子
3. `story-structure` — 信息顺序与叙事推进
4. `on-camera-performance` — Damon 真人怎么站、怎么走、怎么拿产品、怎么说
5. `blocking` — 人物与场景调度
6. `shot-design` — 远 / 中 / 近 / 特写、运动镜头、证明镜头
7. `b-roll` — B-roll 如何承担信息，而不是只做装饰
8. `proof` — 工厂 / 产品 / 价格 / 仓库 / 现场动作怎么形成可信度
9. `pacing` — 镜头长度、信息密度、停顿、自然声
10. `emotion` — 好奇、反差、惊讶、风险、选择困难等情绪机制
11. `retention` — 如何持续给观众“下一个理由”看下去
12. `cta` — CTA 与下一条内容承接
13. `cover-title` — 封面和标题如何强化承诺
14. `editing` — 字幕、屏幕大字、声音、节奏、转场

## 4. 更新闭环 / Learning Loop

```text
外部研究 / 现场观察 / 发布数据
↓
WorkBuddy 写入 research file，并提出 candidate 方法
↓
ChatGPT 判断是否适合 Damon in Linyi
↓
Damon 决定是否测试
↓
状态 candidate → testing
↓
在真实视频中执行
↓
04_performance/videos.md + Damon 现场反馈
↓
ChatGPT 复盘
↓
adopted / 继续 testing / retired
↓
必要时再更新 scripts/README.md 的正式生产规范
```

### 关键原则

- **外部高手的方法 ≠ 自动成为我们的规则。**
- **真实账号数据优先级高于“老师说”。**
- 同一个方法在不同品类 / 场景可能表现不同。
- 不因为一次播放高就永久采用，也不因为一次数据低就立刻废弃。
- 已 approved 脚本保持稳定；新方法优先作用于下一条 draft。

## 5. 当前默认方向 / Current Baseline

截至 2026-09-21，目前已明确有效、但仍可持续优化的方向：

- buyer-question-first：一条视频优先回答一个海外买家问题
- Hook 前置：前 3–5 秒不做长自我介绍
- Damon 必须持续真人出镜，不能退化成纯 B-roll + VO 账号
- 真人动作是内容的一部分：拿货 / 比较 / 查看 / 走进场景 / 站生产线旁
- B-roll 要承担证据功能，不只是漂亮画面
- 多品类穿插：市场广度 + 工厂深度 + 价格/MOQ + buyer mission
- 同品类可深挖，但避免连续霸屏导致账号被误解为单一品类供应商
- approved 脚本使用完整 production package：脚本 + 真人/B-roll + 分镜 + 封面 + Caption + Hashtags + Checklist

> 上述基线来自当前项目决策；后续仍可通过 `candidate → testing → adopted/retired` 机制更新。
